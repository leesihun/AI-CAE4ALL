# Dataset card — shell post-buckling one-to-many benchmark

**Status: pilot only, one known open issue (see &sect;7) blocks calling this final.**
This card describes exactly what the generator in `buckling/src/` produces, as
implemented today — not the aspirational design in `BENCHMARK_DESIGN.md`, where
the two differ. Every number below was read from the code or measured, not
assumed.

---

## 1. What one sample is

A single sample is the terminal state of a **displacement-controlled axial
compression test** on a thin cylindrical shell, carried well past its buckling
limit point. There is no time axis in the released data: `num_timesteps = 1`.
The thing that varies from sample to sample is not the loading history — it is
a geometric imperfection that the model never sees.

```
                nominal geometry (R/t, L/R)  ──┐
                                                ├──►  terminal radial
   imperfection draw  (WITHHELD, never exposed)─┘     displacement field w(θ,z)/t
```

## 2. Geometry (`geometry.py`)

Non-dimensional units throughout: `E = 1`, `ν = 0.3`, reference radius `R = 1`.
Thickness and length are derived from the two control parameters:

```
t = R / (R/t)          L = (L/R) · R
```

Four geometries make up the pilot (all `shape="cylinder"`; the design's cone
and thickness-taper families for the OOD test, `alpha_deg` / `gamma`, are
implemented in `geometry.py` but **not yet generated**):

| R/t | L/R | R | t | L | Batdorf Z | classical λ<sub>half</sub> | classical d<sub>cr</sub> |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 110 | 1.0 | 1 | 0.0090909 | 1.0 | 104.9 | 0.05213 | 5.502e&minus;3 |
| 110 | 1.6 | 1 | 0.0090909 | 1.6 | 268.6 | 0.05213 | 8.803e&minus;3 |
| 230 | 1.0 | 1 | 0.0043478 | 1.0 | 219.4 | 0.03608 | 2.631e&minus;3 |
| 230 | 1.6 | 1 | 0.0043478 | 1.6 | 561.7 | 0.03608 | 4.210e&minus;3 |

`Z = (L²/Rt)·√(1−ν²)`, `λ_half = 1.728·√(Rt)`, `d_cr = t/(R·√(3(1−ν²)))·L`
(classical Donnell critical shortening for a clamped cylinder — the actual
buckling shortening, from `*BUCKLE`, sits at 0.981&ndash;0.995 of this; see
BUILD_LOG.md &sect; Gate G1).

### Mesh

Structured, mapped **S8R** (8-node quadratic reduced-integration shell)
elements, generated analytically (no gmsh — see &sect;5). Element counts are
set from the buckling half-wavelength at **3 elements per λ<sub>half</sub>**
(`elems_per_half_wave=3.0` — the design called for 4; 3 was adopted after
measuring the cost, see BUILD_LOG.md):

| R/t | L/R | n_circ | n_axial | nodes | elements |
|---:|---:|---:|---:|---:|---:|
| 110 | 1.0 | &mdash; | &mdash; | 6,328 | 2,034 |
| 110 | 1.6 | &mdash; | &mdash; | 10,057 | 3,201 |
| 230 | 1.0 | &mdash; | &mdash; | 13,280 | 4,235 |
| 230 | 1.6 | &mdash; | &mdash; | 21,248 | 6,776 |

`avoid_resonant_ncirc()` perturbs the circumferential division count away from
small multiples of any wavenumber in {6..26}, because a structured mesh retains
a discrete C<sub>N</sub> symmetry that is not neutral among buckling modes.

## 3. Boundary conditions

Both ends **clamped**, identical to the eigenvalue gate (`run_g1.py`) so the
buckling problem being solved is the same one the noise-floor was measured
against:

| Node set | DOFs fixed | Value |
|---|---|---|
| `NBOT` (z = 0) | 1&ndash;6 (all translations + rotations) | 0 |
| `NTOP` (z = L) | 1, 2 (lateral translations) | 0 |
| `NTOP` | 4, 5, 6 (all rotations) | 0 |
| `NTOP` | 3 (axial translation) | **prescribed**, ramped to &minus;1.5 &times; d<sub>cr</sub> |

The top edge is free only to translate axially, under a displacement (not
load) boundary condition — i.e. this is a **displacement-controlled** test,
not a force-controlled one. See &sect;7 for why (arc-length is unavailable in
this CalculiX build).

## 4. The withheld variable — the imperfection law

Two components, added to the mid-surface as a **normal offset**:
`x_node → x_node + (w_A + w_B)·n̂`. Full derivation and the mesh-independence
argument are in `BENCHMARK_DESIGN.md` §2; this section states what is
*actually* generated by `imperfection.py`.

### Component A — deterministic per-family signature (`process_signature`)

Ovalization plus a fixed weld-panel harmonic, one axial half-wave:

```
w_A(θ,z)/t = Σ_{l∈{2,3,8,16,24,32}} â_l · sin(πz/L) · cos(l·θ + ψ_l)
```

- `l ∈ {2, 3}` (ovalization, tri-lobing) plus `l = j·N_p` for `j=1..4` with
  **`N_p = 8` fixed globally** (`run_batch.py: N_PANELS = 8`) — **not**
  varied per geometry family as the design envisioned; this is a
  simplification worth revisiting if a future family has a genuinely
  different panel count.
- Amplitudes decay monotonically in `l`; total RMS normalised to
  **0.01 · t** (`comp_a_rms_over_t = 0.01`; chosen by direct sweep — the
  design's original 0.30 t was found to fully dictate the buckling mode and
  destroy the one-to-many structure; see BUILD_LOG.md).
- Phases `ψ_l` are fixed by a seed of `n_panels` (= 8), so **identical across
  every sample in the dataset**, not just per family.
- This component does **not** vary across draws. Its purpose is only to break
  the shell's continuous SO(2) symmetry so the buckle location is not simply
  uniform on the circle.

### Component B — band-limited stochastic residual (`SpectralImperfection`)

This is the withheld random variable. A zero-mean Gaussian random field,
generated in closed form on the unrolled surface and evaluated exactly at the
node coordinates (not interpolated from a grid — see the mesh-independence
note below):

| Parameter | Value | Meaning |
|---|---|---|
| Kernel | Matérn, ν = 1.5 | `nu_matern` in the export |
| Correlation length | `ℓ = 0.70·√(R·t)` | `a_bar = 0.70` |
| Amplitude | `σ = 1e&minus;3 · t` | `sigma_hat = 1e-3` |
| Spectral truncation | `\|κ\| ≤ 8/ℓ` | `kappa_cut_factor = 8.0` |
| Seed | `(geometry, seed)` &rarr; `numpy.random.default_rng(seed)` | one `seed` per draw, 1..80 |

Persisted per draw (`coeffs.npz`, not exported to the HDF5 or the viewer): the
complex spectral coefficients `C_pq` on the wavenumber lattice
`k1_p = p/R`, `k2_q = 2πq/L_p` (`L_p = 2L`, circulant-embedded to avoid a
spurious axial period). Storing coefficients rather than nodal values is what
makes one realization re-samplable on a different mesh or geometry — nodal
values are not portable, the spectrum is.

**The model is never shown either component.** Only the nominal, undisplaced
geometry is written to the training contract (see &sect;6).

## 5. Solver (`ccx.py`, CalculiX 2.22 under WSL)

Three steps in one `.inp`, chained so output requests satisfy CalculiX's rule
that they must appear in the first step of a nonlinear analysis:

| Step | Method | What it does | Increments (as run) |
|---|---|---|---|
| 1 | `*STATIC` | walk from 0 to `handover · d_cr` (handover = 0.70) — the pre-buckling path is linear and cheap | 7 |
| 2 | `*DYNAMIC` (implicit, HHT α = &minus;0.3), mass-proportional damping α = 0.3 | continue to `1.5 · d_cr`, through the limit point | 80 |
| 3 | `*DYNAMIC`, same damping | hold the displacement, let the snap's kinetic energy bleed off | 20 (see &sect;7 — **being revised**) |

Two settings are load-bearing, not defaults, and are documented at length in
`buckling/README.md` because they silently produce a non-buckling or corrupted
dataset if missed:

- Node coordinates written at **`%.13e`** (14 significant digits) — CalculiX
  caps a free-format field at 20 characters; `%.15e` silently corrupts the
  deck (misreported as a bogus Poisson-ratio error).
- **`*CONTROLS, PARAMETERS=FIELD`** with `Rn=1e-6, Cn=1e-8` — CalculiX
  defaults (`Rn=0.005, Cn=0.01`) sit roughly four orders of magnitude above
  the imperfection signal; left at default, every draw returns the same mode
  because the imperfection has no numerical room to act.

**Why displacement control, not arc-length:** CalculiX 2.22 has no Riks /
arc-length method (confirmed by scanning the binary's keyword table). Pure
static displacement control diverges at the limit point
(`*ERROR: too many cutbacks`). Implicit dynamics with mass-proportional
damping is the adopted substitute: inertia carries the solution through the
snap, and damping is meant to bring it to rest afterward.

## 6. What is written to disk

Per draw (`run_batch.py::one`):

| File | Content |
|---|---|
| `w.npy` | radial displacement / t at every mesh node, terminal state, float32 |
| `force.npy` | `(step_time, \|F_z\|)` reaction-force history at `NTOP`, both dynamic steps |
| `coeffs.npz` | the imperfection's spectral coefficients — kept for reproducibility, **never used as model input** |
| entry in `results.json` | geometry, seed, `sigma_hat`, `comp_a`, `n_dominant`, `n_share`, `f_end_over_lin`, `rms_over_t`, `max_over_t`, wall-clock |

`export_hdf5.py` converts a batch into the repo's shared contract:

```
data/{id}/nodal_data   [4, 1, num_nodes]   rows 0:3 = NOMINAL coordinates, row 3 = w/t
data/{id}/mesh_edge    [2, num_edges]
```

Rows 0:3 are the **nominal** geometry, verified bit-identical to
`ShellMesh(...).coords` (`check_leakage`, max abs diff must print `0.0`) — the
perturbed coordinates are never written, because a model that could read them
would be reading the withheld variable directly.

## 7. Confirmed bug: the pilot's fields are transient snapshots, not converged statics

**You asked directly whether this was being recorded transiently rather than at
a converged static state. It is — confirmed two ways, and it is worse than a
simple "run it longer" fix.**

### 7.1 The load is still ringing at the end of every recorded draw

Read directly from `force.npy` of the actual 320 production draws (not a
re-simulation):

| corner | last-third F/F<sub>lin</sub> range as % of mean |
|---|---:|
| R/t=110, L/R=1.0 | 128% |
| R/t=110, L/R=1.6 | 176% |
| R/t=230, L/R=1.0 | 94% |
| R/t=230, L/R=1.6 | 156% |

The load is still swinging by more than its own mean value at the last
recorded increment, everywhere. Step 3 (`n_inc_settle=20`, `t_settle=4.0`) does
not run long enough for the post-snap oscillation to decay; the "terminal"
field is a snapshot at whatever phase of that ringing the solve stopped at.

### 7.2 On the reference corner, 10&times; longer settle converges cleanly — and reveals the amplitude was badly understated

`R/t=110, L/R=1.0`, same seed, `t_settle=40, n_inc_settle=200` (10&times; the
production settle), same damping:

| quantity | production (t_settle=4) | converged (t_settle=40) | ratio |
|---|---:|---:|---:|
| rms(w)/t | 0.4497 | 1.1877 | **2.64&times;** |
| F/F<sub>lin</sub> | 0.5676 | &asymp;0.429&ndash;0.447 | &ndash; |
| dominant n | 10 | 10 | **unchanged** |

Last-third range of rms/t at the long settle: **2.5%** (down from a 128%
force-oscillation at the short settle) — this one is genuinely converged, and
the mode label is stable at n=10 for the entire recorded tail. **But the
converged shell has buckled roughly 2.6&times; deeper than the production
dataset recorded.** The production fields are not merely noisy versions of the
right answer; they are systematically, substantially too shallow. Every
amplitude-based statistic computed from the pilot — rms/t, max/t, the
pairwise-spread numbers in BUILD_LOG.md's G2, the F/F<sub>lin</sub> knockdown
values — is affected. **The dominant circumferential wavenumber is not**: it
matched exactly between the short and long settle, on this corner.

### 7.3 The fix does not generalize by simply scaling time — this is the harder finding

`R/t=230, L/R=1.6` (thinnest, longest — the corner already costing 36.6
min/draw at the *original* short settle) does **not** converge at the same
10&times; settle:

```
rms/t at 0/25/50/75/100% of the settle window: 0.024, 0.440, 1.266, 1.481, 1.710
```

This is **monotonically increasing with an increment that is growing, not
shrinking**, between the last two quarters (+0.214 then +0.229) — not decaying
ringing, an unconverged creep. A longer *fixed-time* window is not a safe,
generalizable fix: it worked on the stiff/thick corner and failed on the
thin/long one, and this corner is also the most expensive to run, so blindly
extending time everywhere would both fail to converge and be prohibitively
costly (the diagnostic alone took 4,646 s = 77 min for one draw).

**Next lever being tested, not yet confirmed:** mass-proportional damping does
not bias the static answer (the dashpot force is proportional to velocity and
vanishes at equilibrium), so increasing `damp_alpha` for the settle step
specifically should converge in *fewer* increments rather than needing a much
longer window. A run at `damp_alpha=3.0` (10&times; production) on the R/t=230,
L/R=1.6 corner is in progress; this section will be updated with the result
before any regeneration is launched.

### 7.4 What this means right now

- **The published sample explorer's field magnitudes and the BUILD_LOG.md
  G2/G3 spread numbers are confirmed incorrect** (understated amplitude by a
  factor that itself varies by geometry, since convergence behaviour differs
  across the box) and must not be cited.
- **The mode label (dominant circumferential wavenumber) survived unchanged**
  on the one corner checked so far, which is encouraging for the
  multimodality claim specifically — but this has only been checked at one
  (geometry, seed) pair and should not yet be generalized to all 320 draws.
- **No regeneration has been launched.** The settle-step fix needs to be
  right, not fast; a second brute-force pass that still doesn't converge on
  the flexible end of the box would cost real compute for no benefit.

## 8. Parameters not yet varied in this pilot

For completeness — these exist in the code but are fixed or unused so far:

- `nu_matern` (Matérn smoothness) — fixed at 1.5, design calls for a sweep
  over {0.5, 1.5, 2.5}.
- `a_bar` (correlation length) — fixed at 0.70, design calls for a sweep.
- Cone (`alpha_deg`) and thickness-taper (`gamma`) families — implemented in
  `geometry.py`, zero draws generated. These are the OOD transfer test (T2,
  T3) and require the equivalent-cylinder check (gate G4) before any cone is
  generated.
- `N_p` (weld-panel count) — see &sect;4, currently one global constant.
