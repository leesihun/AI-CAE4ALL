%   config_train_v3.txt -- the recommended single-GPU DeepJEB recipe. Trains to ex4/.
%   config_train_v2.txt (ex2/) is kept unchanged as the 'v2 control'; the eight
%   single-axis ablations of this recipe live in configs/SDFFlow/arms/.
%
%   Every departure from v2, and why (details: methods/SDFFlow/CLAUDE.md, 'v3 recipe'):
%     - 6144 encoder points (v2: 4096) and 8192 query points. The dataset stores
%       exactly 8192 surface points per shape, so 6144 is a genuine 75% subsample: a
%       different draw every epoch, which is the ONLY surface augmentation this
%       1713-shape train set has. 8192 would NOT be: rng.choice(8192, 8192,
%       replace=False) is a permutation of the one stored point set, and the encoder
%       is permutation-invariant, so the shape's encoder input would be bit-identical
%       across all 500 epochs (v3 briefly shipped that and silently lost v2's
%       augmentation). 6144 keeps more supervision per step than v2's 4096 while the
%       draw stays stochastic; arm A8 (4096) is the density axis. Val/test and the FM
%       latent-cache encode pass subsample deterministically, so every run and every
%       rank still sees the same input there. The query side draws 8192 of the 10240
%       stored sdf_points, also a genuine random subsample.
%     - latent 32 x 32 = 1024 flat (v2: 32 x 64 = 2048), encoder/decoder width 256
%       (v2: 512). On v2, optimizing the latent directly beat the encoder 2.4x -- the
%       latent was over-sized, not under-sized. ~1.7k training shapes; fits 8 GB fp32.
%     - encoder_query_type fps: the latent queries are farthest-point samples of the
%       input cloud (3DShape2VecSet) instead of free nn.Parameters, so each token is
%       anchored to a region of the geometry the attention decoder can address.
%     - kl_weight 0.0000025 on the SUMMED KL = the same total pressure as ex1
%       (1e-5 x 256). v2's 1e-4 x 2048 was 80x tighter than ex1 and its comment pointed
%       the wrong way: 3DShape2VecSet's 1e-3 is a MEAN-KL weight (~6e-8 per element).
%     - posterior_noise_max_scale 1.0 + posterior_min_std_rel 0.02: real
%       reparameterization (v2 sampled at 0.1 sigma, so the decoder never learned to
%       tolerate the posterior width the FM later samples from) with a floor of 2% of
%       each latent dim's mu spread as a variance-collapse guard.
%     - condition_names volume,area: bbox_y has zero train-split std and bbox_x a
%       0.45% CV; conditioning on near-constants only adds noise to the CFG branch.
%     - split_by_parent True: the 2138 shapes are variants of 263 parent geometries;
%       the seed-42 random split put a sibling of every val/test shape into train, so
%       val loss measured memorization. Whole parents now stay on one side.
%     - FM: DiT 384 x 6 x 6 heads (v2: 512 x 8 x 8) for the 1024-d latent; 1000 epochs
%       with a 20-epoch warmup (v2: 300 / 10) -> ~27k updates, enough for EMA 0.999.
%     - vae_best_modelpath: the EMA weights with the best validation SDF loss are kept
%       next to the final checkpoint. The final save to vae_modelpath is unchanged.
%     - seed 0: both stage workers seed torch/numpy/python and the train DataLoader
%       shuffle from it (offset by rank, so ranks do not draw the same stream), so a
%       rerun of this file reproduces itself and any comparison against it has a
%       measurable noise floor. The per-item train surface subsample stays stochastic
%       on purpose -- it is the augmentation. Omit the key for legacy unseeded runs.
