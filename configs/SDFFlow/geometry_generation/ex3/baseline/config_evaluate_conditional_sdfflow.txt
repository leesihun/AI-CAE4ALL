% geometry_generation/ex3 - sdfflow on MCB (5-class nut subset); held-out CONDITIONAL benchmark
%   of the FM trained by the paired config_train_sdfflow.txt: can the generator realise the
%   condition vector of a part it never saw? Measurement config, not a generator (no mesh
%   export). For each scored shape the target is that shape's TRUE stored condition vector (the
%   checkpoint's 11 names: 5 geometric, 5 class_* one-hots, hole_count), and every method starts from
%   the SAME base noise (paired z0 seeded by eval_seed and the shape index), so method
%   differences are not noise differences:
%     plain      -- one conditional sample per shape (ode_steps NFE)
%     rejection  -- best of candidate_multiplier samples by geometric condition error
%     e2         -- plain + newton_rounds of proxy-Jacobian Newton correction on the Marching
%                   Cubes volume/area (needs descriptor_calibration_path)
%   Per method and name it reports the relative error |actual - target| / |target| (median,
%   p95), valid / watertight rates, latent RMS drift from plain, NFE and wall time.
% Run order: config_train_sdfflow.txt -> config_calibrate_sdfflow.txt -> this. The calibration
%   is fitted on the TRAIN file's val split and bound to this exact vae.pth / fm_best.pth pair.
% dataset_dir is ex3_mcb_infer.h5 (330 held-out parts, rebuilt 2026-10-01). overfit_all_shapes True makes the whole
%   file the test split -- a split selector here, as in config_evaluate_sdfflow.txt; nothing
%   trains. eval_num_shapes 64 is a seeded random subset; 0 scores all 330 at ~5x the cost.
% SCOPE: e2 optimises volume and area only (the only names with a soft proxy); bbox_x/y/z are
%   scored but never optimised, and a latent step taken for volume/area can move them as a
%   side effect. Compare methods on the printed PAIRED block (the shapes every method could be
%   measured on): an unpaired median is taken over a method-selected subset.
% The class_* one-hots and hole_count ARE conditioned on, but they are not geometric
%   descriptors the evaluator can measure on a decoded mesh, so they steer every method and are
%   not scored; class fidelity is not measured here.
% max_condition_z 10 + condition_ood_policy error: equal to the training condition_clip 10, so a
%   rare-class one-hot (sqrt((1-p)/p) sigma) passes, and a target the training clip would have
%   cut fails loudly instead of being scored against a value it was never asked for.
% newton_measure_resolution is absent on purpose: it follows mc_resolution (128), the grid the
%   calibration was fitted on; check_compatible refuses the artifact on a mismatch.
% condition_audit geometric: the 5 geometric names are measured on the decoded mesh -- no FEA
%   backend is involved.
% Writes eval_conditional.json + eval_conditional.csv under output_dir.
% Reference: https://doi.org/10.1007/978-3-030-58523-5_11 ; https://arxiv.org/abs/2301.11445 ; https://arxiv.org/abs/2210.02747
% No source HDF5 writes. Checkpoints are created by the paired training config.
