%   *** THIS IS THE PILOT ITSELF: 1 GPU, 150 epochs, run this FIRST ***
%   Ablated on TWO synthetic benchmarks with opposite outcomes:
%     - geometry-informative (mesh curvature determines warpage amplitude,
%       plausibly like real board layout/thickness -> warpage): this recipe
%       measured corr(t, generated mean) -0.03 -> +0.93..+0.98, wild-draw
%       rate 30.5% -> 0%, energy-score excess over the oracle floor down 13x,
%       and every metric kept improving with more training budget (confirmed
%       at 2.5x epochs / 2x samples-per-step).
%     - geometry-UNINFORMATIVE (target amplitude drawn independent of the
%       mesh): the SAME recipe made wild rate WORSE than the old recipe
%       (43.8% -> 47.9%), and naively combining the energy-score term with a
%       KEPT conditional prior on that data was worse still (up to 89% wild,
%       even on the training split -- not a generalization gap, an outright
%       bad fit). Root cause: an energy-score term is only as trustworthy as
%       the z-sampler it is scored against; a conditional prior with nothing
%       informative to condition on produces high-variance garbage, and
%       forcing the decoder to fit that garbage backfires.
%   Real b8/SAOI warpage almost certainly falls in the first regime (board
%   geometry/layout should correlate with warpage mode+amplitude, similar to
%   MeshGraphNets' usual deterministic case) -- but VERIFY before committing
%   compute: run this config (or a short-epoch subset) alongside train1, then
%   compare both with:
%       python misc/eval_distribution.py --config <cfg> --split test --k 50
%   on the resulting checkpoints. Confirm gamma_es (train9) reduces the wild
%   rate and moves the rank histogram toward flat/uniform vs train1 -- do NOT
%   assume it from this ablation alone. If it does not, fall back toward
%   train1's weights (mmd 0.2, prior_nll_weight 1.0) rather than this file,
%   and ask for a fresh ablation grid run directly against a subset of the
%   real dataset instead of a synthetic stand-in.
%
%   What changed vs config_train1.txt:
%   1. The learned conditional-prior network is DROPPED ENTIRELY
%      (prior_type none). It is not just unneeded -- ablation showed it is
%      ACTIVELY WORSE than plain N(0,I) noise at inference, because the
%      decoder's graph input already carries geometry through the same
%      message-passing backbone MeshGraphNets always uses; z only needs to
%      carry the part of the field the graph can't predict (the irreducible
%      per-sample residual). Training a second network to reproduce a
%      moving, weakly-coupled posterior solves a problem that doesn't need
%      solving, and the Euler-integration sampling error at inference is
%      exactly where the "10% totally unreasonable" draws were coming from.
%   2. gamma_es (NEW): the only loss term that ever decodes a
%      generatively-sampled z (z ~ N(0,I), matching what inference/rollout.py
%      actually draws when there is no conditional prior) and scores the
%      resulting FIELD -- via the energy score, a strictly proper rule that
%      penalizes wrong location AND wrong spread simultaneously. Every other
%      term here (recon, mmd) only ever sees POSTERIOR z; without gamma_es
%      the decoder never meets a generatively-sampled z until inference.
%   3. lambda_mmd / beta_aux -> 0. With gamma_es active, both were ablated
%      to zero measurable effect (tie within noise) on generation quality --
%      they were only needed to keep the aggregate posterior near N(0,I) so
%      the (now-removed) conditional prior had a stable target to chase. If
%      you also need faithful posterior-conditioned reconstruction for a
%      SPECIFIC known input (not just generation from geometry alone), it is
%      still safe to raise beta_aux back to 1.0 -- just re-run the ablation
%      metric (wild rate / energy score on held-out geometry) before trusting
%      the result at this larger scale.
%   4. best_by crps (NEW): checkpoint selection now uses the inference-
%      mirroring learned/N(0,I)-prior CRPS instead of posterior validation
%      loss. Posterior recon can keep improving epoch over epoch while the
%      generative path silently degrades (this is exactly what train1's
%      "corr 0.996 recon, corr -0.03 generation" result shows) -- CRPS is
%      the metric that tracks what this model is actually used for.
%   5. es_start_epoch (NEW, 50): ES costs es_samples extra full forward
%      passes per step; the first ~5% of a 1000-epoch run has an
%      undertrained decoder with nothing informative to score, so this skips
%      ES until the recon path has stabilized, at no quality cost.
%   6. es_samples 2 (not 4): the toy-scale ablation used 4 comfortably, but
%      b8/SAOI meshes are far larger -- start at 2 (the minimum for an
%      unbiased spread estimate) and raise only if VRAM/wall-clock allow;
%      re-check wild rate / energy score before committing to a higher value.
%
%   Everything below this line that ISN'T explicitly loss/prior-related
%   (dataset, architecture, multiscale, AMP, etc.) is UNCHANGED from
%   config_train1.txt -- this is a loss-function fix, not an architecture
%   change.
%   ============================================================
